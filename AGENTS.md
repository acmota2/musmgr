# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project Overview

MusMGR is a web application for managing a composer's repertoire and performance events: pieces, events (concerts, premieres, workshops, etc.), and associated files (scores, recordings, photos, PDFs). It is a repertoire manager and event tracker &mdash; **not** a streaming or playback platform.

The repo is a monorepo with two deployable halves:

- `backend/` &mdash; Go (Gin) REST API. Runs **two routers**: a public, GET-only API and an admin API with mutations.
- `frontend/` &mdash; SvelteKit SPA, built in two modes (admin and public) from the same codebase.

## Repository Layout

## Development Setup

Environment comes from the Nix flake (auto-loaded via direnv `use flake` in `.envrc`); `.env` at repo root holds local secrets/ports and is loaded by the Taskfile.

```sh
task install-deps                                  # go mod download + pnpm install
task start-containers STAGE=bootstrap              # postgres + goose migration job
task start-containers STAGE=local                  # + minio, adminer, backend (go-gin)
task start-containers STAGE=dev                    # + frontend-admin (:3000), frontend-public (:3001)
task stop-containers STAGE=dev
task db:populate                                   # seed fixtures via backend/cmd/populate
```

Run pieces locally (outside compose) if needed:

```sh
cd backend && go run ./cmd/musmgr --storage-type LOCAL   # flags: --storage-type MINIO|LOCAL, --admin-port 4700, --public-port 4701
task frontend:admin-dev                                  # admin frontend on :5173
task frontend:dev MODE=public API_URL=http://localhost:4701  # public frontend on :5174
```

Ports: backend admin `4700`, public `4701`; frontend dev `5173` (admin) / `5174` (public); compose frontends `3000`/`3001`; postgres `5432`; MinIO `9000`/`9001` (console); Adminer `8080` (overridable via `ADMINER_PORT`).

## Database Workflow (order matters)

1. `task db:create-migration NAME=foo` -> creates a file in `backend/db/migrations/`; edit its SQL.
2. `task db:migrate` -> apply with goose.
3. `task db:dump-schema` -> regenerates `backend/db/schema.sql` from the live DB (pg_dump, excludes `goose_db_version`).
4. `task db:create-models` -> `sqlc generate` regenerates `backend/internal/model/` from `schema.sql` + `queries.sql`.

Rules:

- `backend/internal/model/` is **generated** &mdash; never edit it by hand. Put query changes in `backend/db/queries.sql`, then re-run `db:create-models`.
- `backend/db/schema.sql` is a pg_dump &mdash; never hand-edit; change migrations and re-dump.
- sqlc config: package `model`, output `../internal/model`, `pgx/v5`, `uuid` -> `github.com/google/uuid.UUID`.

## Backend Architecture

- `main.go` builds a `pgxpool`, a storage backend (`MINIO` default, `LOCAL`), a `BaseHandler` (pool + sqlc `Queries` + logger) and a `FilesHandler` (Storage + PdfGenerator), then starts both routers.
- **Public router** (port 4701): GET-only; CORS restricted to `ALLOWED_PUBLIC_DOMAINS`.
- **Admin router** (port 4700): all public routes plus POST/PATCH/PUT/DELETE; CORS restricted to `ALLOWED_ADMIN_DOMAINS`; 64 MiB multipart limit.
- Middleware sets a `Scope` (public/admin) and `FileClassification` (public/protected) per request; `FileClassificationBlocking` blocks access to protected files on the public router. `middleware.RequirePerm(policies.PermX)` enforces the permission lattice &mdash; admin scope is always allowed.
- DB + storage operations that must stay consistent run inside a transaction via `BaseHandler.DBTransaction`. Storage deletion on file/piece/event delete is best-effort (async goroutine, `BestEffortDelete`).
- Domain: `composer` (singleton row), `pieces`, `events`, `files` (`parent_id` links derivative files), `pieces_events` join table; enums: `event_type`, `file_type`, `file_origin`, `instrumentation_name`. Schema lives in the `musmgr` namespace.

## Frontend Architecture

- One codebase, two builds: `VITE_FRONTEND_BUILD_MODE=admin|public` (set by `build:admin`/`build:public` scripts and compose build args) -> exported as `IS_ADMIN` from `src/lib/app/index.ts`. Use `IS_ADMIN` to gate admin-only UI.
- `src/hooks.server.ts` proxies `/api/*` requests server-side to `API_URL` (admin -> `:4700`, public -> `:4701`). Client code calls `/api/...` and never the backend directly.
- API clients live in `src/lib/server/<entity>.ts` with snake_case interfaces mirroring backend JSON.
- Routes: `pieces`, `events`, `setup` (initial composer setup), `health`.

## Verification Commands

```sh
# Backend
task backend:lint        # go vet ./...
task backend:format      # gofmt -w .
cd backend && go test ./...

# Frontend
task frontend:lint       # biome lint
task frontend:format     # biome format --write
cd frontend && pnpm check            # svelte-check
cd frontend && pnpm test:unit -- --run   # vitest
cd frontend && pnpm test:e2e          # playwright (e2e/ dir may not exist yet)
```

## Conventions

- **Commits**: Conventional Commits (commitizen, `cz_conventional_commits`). Never bump versions manually &mdash; CI (`.github/workflows/versions.yaml`) auto-bumps on push to `main` and updates `.cz.toml` + `frontend/package.json`.
- **Images**: semver tags trigger `.github/workflows/images.yaml`, which builds/pushes 4 GHCR images: `backend`, `goose-job`, `frontend-public`, `frontend-admin`.
- **Git hooks** (lefthook): pre-commit runs `gofmt` + `go vet` on staged Go files and `biome check --write` on staged frontend files; pre-push docker-builds any changed service (`go-gin`, `frontend-admin`, `frontend-public`, `database`).
- **Generated files**: `backend/internal/model/*` (sqlc), `frontend/.svelte-kit/` &mdash; never hand-edit.
- **Docs typography**: the em dash and en dash are hard to type on a keyboard, so write them in documentation as the HTML entities `&mdash;` and `&ndash;` instead of the literal characters. Do not use the arrow character (`→`) in docs; use `->` or plain words instead.

## Gotchas

- `ALLOWED_ADMIN_DOMAINS` / `ALLOWED_PUBLIC_DOMAINS` are **JSON arrays** of origins (e.g. `'["http://localhost:5173"]'`), not comma-separated strings.
- `STORAGE_TYPE` in `.env` is used by the populate tooling; the backend binary takes `--storage-type` as a CLI flag (default `MINIO`).
- The frontend has Playwright/Vitest configured but no test files yet; `pnpm test` will fail on missing e2e dir until tests are added.
- The `database` compose service (goose job) only runs in the `bootstrap` profile; in `local`/`dev` run migrations with `task db:migrate`.
- File upload endpoints accept multipart; keep the admin router's 64 MiB `MaxMultipartMemory` in mind when raising limits.
